# Checklist de revisión cruzada y Feria de Logros

Plantilla para organizar la preparación y registrar observaciones reales. Completar roles, fechas, tiempos y criterios según la guía docente; no marcar tareas ni atribuir resultados antes de realizarlos.

## Antes de presentar

- [ ] Confirmar con el docente el horario, la duración de cada ronda y el rol asignado a cada integrante.
- [ ] Abrir el portal desde la URL de GitHub Pages prevista y comprobar que corresponde al commit de entrega.
- [ ] Probar la navegación, búsqueda, filtros de docentes y categorías, carrusel, quiz y galerías.
- [ ] Revisar las nueve fichas y confirmar docentes, enlaces y evidencias; dejar los datos no confirmados como pendientes.
- [ ] Comprobar la página en el equipo que se utilizará y en un teléfono físico.
- [ ] Confirmar la autorización de las personas que aparecen en la fotografía de BTVDS 3.8 o retirar esa imagen.
- [ ] Preparar un recorrido breve por el proyecto y repartir las explicaciones sin atribuir aportes que no se puedan demostrar.
- [ ] Revisar el estado de Git, los commits y la etiqueta de versión prevista; no crear etiquetas históricas sin evidencia.
- [ ] Tener un respaldo del enlace y el contacto del integrante que atenderá problemas técnicos.
